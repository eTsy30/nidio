# Push для чата

Реализованы: подписки нескольких устройств, кнопка включения/отключения в профиле,
имя и текст сообщения, подписи для фото/файла, открытие `/chat` по нажатию.
Автор не получает push. Видимый чат с фокусом на любом устройстве подавляет push
получателю на всех устройствах. Свёрнутая/неактивная вкладка не подавляет push.

## Настройка перед проверкой на устройствах

1. Создать VAPID-ключи: `pnpm --filter api exec web-push generate-vapid-keys`.
2. В окружении API задать `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`,
   `VAPID_SUBJECT=mailto:<реальный контакт администратора>`.
   Приватный ключ хранить только на сервере, не коммитить. Публичный ключ клиент
   получает через авторизованный `GET /push/config`.
3. Применить миграцию к нужной базе: `pnpm --filter api exec prisma migrate deploy`.
   Для production передать `NODE_ENV=production`; конфигурация Prisma выбирает
   `.env.production`, иначе `.env.development`. Затем `pnpm --filter api exec prisma generate`.
4. Собрать веб: `pnpm --filter web build`, запустить API и production web.
   Сборка использует webpack, необходимый текущей интеграции Serwist.
   В `next dev` service worker отключён настройками проекта.
5. Использовать HTTPS (localhost подходит только для локального браузера).
   На iPhone/iPad установить приложение на экран «Домой», открыть оттуда,
   затем нажать «Включить уведомления» в профиле. Требуется iOS/iPadOS 16.4+.
   Источник: https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/

Если сервер ещё не настроен, кнопка показывает объяснение. Запрос разрешения
производится только по нажатию. Отключение и выход из аккаунта отзывают подписку
текущего устройства, другие устройства остаются подписанными.

## Проверка двумя аккаунтами одной пары

- Включить push у Б на телефоне и компьютере; отправить сообщение от А:
  при закрытом чате оба устройства Б получают имя и текст, А ничего не получает.
- Открыть чат Б на одном устройстве и дать ему фокус: новое сообщение от А
  появляется через WebSocket, push не приходит ни на одно устройство Б.
- Свернуть приложение / переключить вкладку / перейти в профиль: следующее
  сообщение вызывает push. Проверить также повторное подключение WebSocket.
- Нажать push при открытом и закрытом приложении: открывается `/chat`.
- Отключить push на телефоне: компьютер продолжает получать уведомления.
- Выйти из аккаунта: это устройство больше не получает сообщения старого аккаунта.
- Запретить разрешение браузера: профиль показывает инструкцию для разблокировки.
- Повторно вызвать обработку того же messageId: повторных push нет.

## Автоматические проверки

`pnpm --filter api exec jest --runInBand --watchman=false push.service.spec.ts`

`pnpm --filter api exec tsc --noEmit`

`pnpm --filter web build`

Тесты API используют mock push-провайдера, реальную доставку на устройства не доказывают.
Фото/файлы покрыты форматированием уведомления; текущий метод отправки чата
пока требует текст. Добавление загрузки вложений — отдельная задача.

## Ограничения первой версии

- Отправка выполняется после сохранения сообщения без устойчивой очереди.
  Перезапуск процесса в этот момент или сбой провайдера может привести к пропуску.
  Автоматических повторов нет, чтобы не дублировать неопределённый результат отправки.
- `PushDelivery` — атомарная отметка попытки по устройству и сообщению, а не
  подтверждение показа уведомления. Записи удаляются вместе с сообщением/подпиской.
- Сервер не читает browser `Notification.permission`: клиент проверяет разрешение
  при включении, а ответы провайдера 404/410 удаляют устаревшие подписки.
- Присутствие имеет срок 45 секунд и heartbeat 20 секунд; отключение WebSocket
  очищает запись. При внезапном обрыве возможна задержка распознавания закрытого чата.
- Календарь и задачи не входят в эту реализацию.
