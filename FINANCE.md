# Финансы

Раздел `/finances` доступен через основную навигацию и использует существующие авторизацию, связь пары и UI kit.

## Возможности

- **Копилки:** цели с датой, значком и цветом из токенов; пополнение, снятие с подтверждением, история с авторами, прогресс, изменение и удаление.
- **Карты:** поиск, категории, избранное, сортировка по недавнему использованию, фото, копирование номера и полноэкранный показ. QR формируется только при явном выборе формата; EAN-13 проверяется по контрольной цифре. Неизвестный формат отображается номером.
- **Бюджет:** доходы и расходы, отдельные общий и периодический балансы, фильтры, диаграмма категорий, сравнение месяцев, месячные лимиты и CSV.

Валюту BYN/EUR/USD/RUB выбирают над вкладкой. Суммы разных валют не складываются и не конвертируются. Это ручной учёт: пополнение копилки не создаёт автоматически расход в бюджете.

API `/finance` хранит данные в PostgreSQL. Суммы записываются целыми минимальными денежными единицами, остатки вычисляются из истории. UUID запроса защищает добавление денежных операций от повторной отправки. Снятия сериализуются в транзакции: параллельные запросы не позволяют уйти в минус.

Каждый запрос проверяет текущую пару пользователя на сервере. Изображения хранятся в существующем S3-совместимом хранилище и выдаются только через защищённый маршрут карты. Общий маршрут изображений не выдаёт финансовые файлы.

После изменения сервер отправляет `finance.updated` обоим участникам; клиент перечитывает данные. Также обновление происходит при восстановлении соединения, возвращении фокуса и каждые 30 секунд. Новый раздел требует сети для загрузки и сохранения; его ответы и фотографии не кешируются service worker. Старый механизм офлайн-взносов из отчёта о готовности сюда не подключён.

## Подключение

Перед использованием раздела нужно применить новую миграцию к целевой базе обычным процессом развёртывания: `pnpm --filter api db:deploy`. Команда применяет все ожидающие миграции, поэтому перед запуском следует проверить их список. В этой работе миграции применялись только к отдельной временной тестовой базе; рабочая база не изменялась.

Для фотографий нужны действующие настройки существующего S3/MinIO. Без хранилища карта с номером сохраняется, а ошибка загрузки фото отображается отдельно.

## Проверки, 19 октября 2026

- Web и API: lint, typecheck и production build прошли.
- `pnpm --filter web test:finance`: суммы, границы периодов, прогресс, EAN-13 и безопасный CSV — прошли.
- Интеграционный тест на временной PostgreSQL: применение миграций, CRUD, чтение после повторного подключения, доступ партнёров и изоляция другой пары, повторные запросы и конкурентные снятия — прошёл. Временная база удалена.
- Серверный прогон без HTTP-тестов: 84 теста прошли; один существующий тест календаря (`event-occurrences.spec.ts`, пересечение повторяющегося события с предыдущего дня) падает. Он не относится к финансам и не исправлялся в этой задаче.
- HTTP-тесты добавлены, но не выполнены: запуск с открытием портов вне песочницы не был разрешён.
- Браузерная приёмка на 320/375/768/1280 px, обе темы, клавиатура, два одновременно открытых аккаунта, загрузка фото через UI и сканирование кода кассиром **не выполнены**: браузер недоступен. Сборка и серверные тесты не заменяют эти проверки.
