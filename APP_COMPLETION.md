# Доведение Nidio до готовности

Цель: простой, функциональный, быстрый и устойчивый интерфейс, которым можно пользоваться без интернета. Работа продолжается; приложение ещё не принято как полностью готовое.

Уточнение пользователя от 16 октября 2026: «Бюджет», «AI-помощник» и «Пространство» оставить как есть, вернуться к ним позднее. Не включать реализацию этих трёх разделов в текущие изменения. Чат удалён из приложения и API.

## Реализованный офлайн-фундамент

- Снимок сохраняется локально в текущем браузере, максимум 2 МБ, версия схемы 1. Он не является резервной копией; очистка браузерных данных удаляет его.
- Кеш восстанавливается для ранее вошедшего пользователя. Отсутствие сети не равнозначно истечению сессии; подтверждённые 401/403 очищают её.
- Запись HTTP-ответов API и сторонних ресурсов в общий service worker cache запрещена. Личные данные сохраняются отдельным механизмом приложения.
- Офлайн-выход удаляет снимок и ставит отметку pending logout. Следующий онлайн-запуск завершает серверный выход перед восстановлением сессии.
- Ошибка обновления данных не удаляет последние успешные данные из локального снимка.
- Отметки взносов в копилке записываются в localStorage до подтверждения пользователю. Очередь разделена по аккаунту и паре; повторная отправка идемпотентна. Подтверждённый ответ сохраняется в снимок до удаления команды. Ошибки доступа и смена пары отображаются явно; выход предупреждает об удалении неотправленных отметок.
- При ошибке сохранения снимка (включая нехватку места) отображается предупреждение; успешная запись убирает его.
- Остальные мутации пока не ставятся в недолговечную скрытую очередь React Query: без сети возвращается ошибка, интерфейс не обещает сохранение.

## Проверки

`pnpm --filter web test` запускает имеющиеся frontend regression scripts, включая тесты офлайн-хранения, сессии и очереди отправки. Также обязательны `pnpm --filter web lint`, `pnpm --filter web typecheck`, production build и браузерная приёмка. Проверка с моками подтверждает отдельные состояния, но не заменяет реальный офлайн-запуск с service worker.

В доступной сессии инструмента браузер не подключён. Это ограничивает визуальную и браузерную приёмку, но не блокирует дальнейшую реализацию и серверные/модульные проверки.
