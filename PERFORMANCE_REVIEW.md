# Проверка отзывчивости — 25 октября 2026

## Проверено

- `GET https://nidio.onrender.com/health`: HTTP 200, `{"status":"ok"}`,
  0,886 с в одном замере с рабочей машины. Это не p95 и не измерение холодного старта.
- Локальные HTTP-тесты GET/HEAD проходят; маршрут публичный, без обращения к БД,
  с `Cache-Control: no-store`. Это проверка работы процесса, не готовности базы.
- Перемещение задач и колонок уже обновлялось оптимистично.

## Изменения

- Выполнение, повторная активация и удаление задачи обновляют доску, список задач
  и существующий кэш «Дня» до ответа сервера. Ошибка восстанавливает только эту
  задачу, сохраняя параллельные изменения других задач, и показывает уведомление.
- Для совместной задачи первая отметка не завершает задачу за обоих участников.
- После группы параллельных изменений статусов выполняется одна итоговая
  инвалидация вместо перезапроса после каждого ответа.
- Финансы раньше монтировали сразу копилки, карты и бюджет, скрывая два раздела
  HTML-атрибутом hidden. Теперь монтируется только выбранный раздел, код остальных
  загружается через React.lazy по необходимости. Копилка также загружается отдельно.
- Suspense добавлен для этих модулей и экрана задач с useSearchParams.
  Сетевые запросы React Query по-прежнему используют свои состояния загрузки:
  Suspense сам по себе не ускоряет сервер и не обрабатывает обычный useQuery.

## Что ещё измерить на production

- Записать на iPhone открытие PWA, переходы и выполнение задач: Network + Performance,
  включая медленную сеть и первый запрос после долгого простоя. Без этого нельзя
  обещать конкретное улучшение LCP/INP или времени запуска.
- `/finance` всё ещё возвращает общий набор данных. Проверить размер ответа и
  время обработки у пары с большой историей; при подтверждённой проблеме разделить
  запросы и добавить пагинацию истории.
- Доска запрашивается при каждом монтировании/фокусе. Увеличивать staleTime стоит
  после проверки доставки обновлений партнёра, чтобы не ускорять ценой устаревших данных.
- Проверить повторные быстрые действия и откат при 403/500 на реальном UI.
  Автотесты покрывают преобразование кэша и независимый откат, но не заменяют эту проверку.
- Финансовые операции не получили общий «оптимистичный успех»: суммы требуют
  согласования с сервером и защиты от повторных транзакций. Существующая очередь
  копилок остаётся отдельным механизмом.

## Исправления после аудита

- Поиск повторений календаря перескакивает к нужному периоду. Регрессия с ежедневной серией 2023 года и просмотром октября 2026 года покрыта тестом. Правила переполнения месяцев и високосных дат сохранены.
- При восстановлении сессии показывается общий LoadingState. Ошибка обновления финансов больше не скрывает закешированные данные; отказ в доступе по-прежнему скрывает.
- Карты, копилки и бюджет используют отдельные запросы. Истории — по 50 записей с устойчивым порядком по дате и id. Балансы, статистика, лимиты и взносы по расписанию агрегируются по всем записям в БД; отменённые взносы исключены. CSV читает все страницы по текущему фильтру.
- Проверка на изолированной локальной PostgreSQL: 125 операций октября, операция сентября, 125 взносов с отменой и снятиями. Проверены полные суммы, фильтры, границы периода, одинаковые даты сортировки, удаление записи-курсора и изоляция личных целей/пар.
- На этой фикстуре сериализованный JSON старого общего ответа — **90 490 байт**, нового ответа карт — **642 байта**, примерно на 99,3% меньше. Это сравнение JSON до сжатия, не результат измерения LCP или скорости продакшена.
- При рабочем WebSocket нет запросов по 30-секундному таймеру; при отключении включается резервный опрос. Переподключение сверяет данные. Собственное сохранение не запускает дополнительную сверку из socket-обработчика во время мутации.
- `/health/ready` проверяет БД и ранее проблемную колонку с общим сроком ответа 2 секунды. `/health` остаётся независимым от БД.
- Добавлены структурированные HTTP-метрики и опциональная выборка Web Vitals. Параметры включения и порядок деплоя описаны в README.
- Web-тесты теперь входят в `pnpm test`; финансовые интеграционные проверки добавлены в CI.

Реальные p75 LCP/INP на iPhone и p95 API после деплоя ещё нужно измерить. Старый `/finance` временно оставлен для совместимости со старыми вкладками/PWA; удалить его можно после завершения обновления клиентов.
